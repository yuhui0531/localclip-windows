# Syntax highlighting diagnosis

用户报告：语法没高亮。

- [x] 检查卡片、详情、富文本和文件预览链路，以及 macOS 只读参考实现。
- [x] 复现长代码：0.1.6 的 TextPreview 在超过 16,384 UTF-16 单元后直接返回完整纯文本，导致已有高亮完全关闭。新增测试在修复前失败。
- [x] 确认 HTML 分支：编辑器同时提供 HTML 与正文时，详情无条件选择富文本 iframe，跳过正文识别。
- [x] 对比原有边界：短片段 relevance < 3 不识别是既有 macOS 兼容规则；卡片使用 180 字符摘要，当前未收到用户的具体位置、语言和示例，不能认定全部症状已解释。
- [x] 自检：问题属于渲染分支逻辑；不改拖动、输出、存储、OCR 或杀毒配置。无需改变用户的功能要求。

修复：详情用有界前缀生成高亮范围，再追加由 React 转义的完整尾部。防止 UTF-16 代理对在分界处被拆开，缓存仅保留有界前缀。已识别为代码的 HTML+文本条目使用统一代码显示；普通富文本仍使用原来的隔离 iframe。着色预算保持 16,384 单元，超出部分保持可读正文，不承诺全文着色。

验证：15 项代码/渲染回归通过；9 项 Chromium 布局测试通过，包含实际颜色、完整正文相等、富文本保留、图片缩放与拖动画布。尚未完成新版本原生验证/安装，用户具体复现样本待补充。
